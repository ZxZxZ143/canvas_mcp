# Threat model

Assets: Canvas token; private course/submission/grade data; local project files; artifact bytes and integrity; connected-user identity; agent instruction authority; host CPU/disk/network. Attackers may control coursework text, a linked file, a Canvas/CDN response, DNS/redirect data, an MCP argument or cursor, or a future unrelated authenticated user. A hostile same-OS-user administrator/process is outside the personal MVP isolation guarantee. Canvas permission grants can be broader than this application's own-user policy.

Severity below is impact without controls, not a claim that an implemented system is secure. Controls are design requirements owned by the indicated boundary and linked to planned security tests.

| Threat / impact | Scenario | Required boundary and mitigation | Residual / test |
| --- | --- | --- | --- |
| CRITICAL: credential theft | Token in exception, serializer, debug log, signed URL output or child environment | Credential source/API client only; output/log allowlists; isolated inspection; no ambient auth in downloads | Same-user process compromise outside guarantee; sentinel-secret scan across all outputs |
| HIGH: prompt injection | Professor/file/title instructs agent to reveal env, execute code or upload project | AGENTS/skills retain authority; external text/bytes remain untrusted; server has no commands/generic requests; host must enforce tool policy | Injection cannot be solved by text labels; adversarial host workflow tests |
| HIGH: arbitrary network/SSRF | HTML/pagination/redirect points at metadata service or a private IP | Fixed API routes, exact origins, DNS+socket target validation, revalidation every hop; no proxy/env bypass | Selected HTTP client's behavior requires verification; rebinding, IPv6 and redirect tests |
| HIGH: credential forwarding | Canvas download redirects to an attacker | Token on fixed initial route and exact-origin Canvas redirects only; external transition permanently clears auth; exact origins and pinned DNS | Wire-header and multiple-hop tests; no signed URL logs; ADR-007 |
| HIGH: arbitrary local write | Filename `../AGENTS.md`, `CON`, UNC, ADS or symlink swap | Generated paths, owner-only root, handle-based confinement, exclusive creation, no-follow/reparse policy | Per-platform race behavior must be proven; Windows and POSIX malicious-path suite |
| HIGH: parser execution / archive bomb | PDF action, macro, notebook cell or recursive archive activates | No parser in credential server; restrictive format policy; isolated no-network read; archive expansion not automatic | Third-party parser vulnerabilities remain; sandbox/container limits and format corpus |
| HIGH: object/tenant confusion | Caller uses another course's file, another user's grade or same numeric ID on another institution | Server-bound scope, current-user operations, parent-child checks, connection identity validation; remote caller auth required | Canvas token may have staff privileges; explicit learner policy tests, no arbitrary student selector |
| HIGH: stale connection | Token changes subject but old file/cursor is reused | Verify authenticated subject/origin; invalidate namespace/capabilities on binding change | Same-subject revocation races; reauthorize on artifact/cursor use |
| MEDIUM: cursor tampering | Reuse cursor for another filter/course, inject upstream URL | Random server references, scoped query/version/expiry binding and bounds | Live view can change; cursor misuse and restart tests |
| MEDIUM: resource exhaustion | Many pages/courses/retries, giant body, stalled stream or full disk | One aggregate budget, monotonic deadline, process concurrency, per-stream/serialized limits, artifact quotas | Remote per-user rate/admission controls deferred; budget accounting tests |
| MEDIUM: false academic status | Nulls/errors become unsubmitted, graded implies submitted, overridden date ignored | Availability states, independent status flags, effective own-user dates, coverage warnings | Upstream may be inconsistent; mapping/partial-result fixtures |
| MEDIUM: unsafe data presentation | Active HTML, terminal escapes or malicious filename in UI/log | Bounded inert-text projection; typed fixed codes; no content logging | Host rendering must preserve plain-data treatment; malicious-string tests |
| MEDIUM: artifact leakage or staleness | A handle/path is guessed, reused after expiry, or bytes replaced | Unguessable ID + scope/permission checks, digest and opened-file verification, TTL and registry | Path is not a sandbox; trusted host needs isolated read handoff; cross-scope/TOCTOU tests |
| MEDIUM: excessive retention | Logs/caches/temp files accumulate private course data | No persistent data/cache, quotas/TTL, scoped safe cleanup, allowlisted stderr | Host logs/backups/copies outside server lifecycle; cleanup and policy documentation tests |
| HIGH (future): unauthorized writes | Read token/client reused for submitting under injected instructions | Separate commands/capabilities/authorization, exact-action approval, audit and replay limits | Not implemented; separate threat review required before adding any write tool |
| HIGH (future): remote auth confusion | Treat Canvas token as MCP caller auth or connect arbitrary institutions | Separate inbound/outbound auth, ownership registry, explicit origin onboarding, encrypted subject-scoped secrets | Remote/OAuth deployment blocked until dedicated security review |

Security acceptance means demonstrating the controls in tests and host integration, not merely having this table. The mandatory critic findings and architect dispositions are recorded in [review-summary.md](review-summary.md).
